# INC-M03-106-G38 — Errores de configuración del clasificador Edge

| Campo | Valor |
|---|---|
| Casos afectados | TC-M03-083 (umbrales ausentes), TC-M03-095 (umbral en cero), TC-M03-122 (parámetros de severidad ausentes) |
| Requerimiento | RF-55, RF-55.1 (RF-17, RF-62) |
| Equipo | IoT/AIOT — firmware Edge (Raspberry) |
| Rama | `fix/inc-mm03-159-thi-nrc` (junto con G37, G39, G40, G45–G50 y G54) |
| Fecha | 2026-10-29 |
| Estado | Corregido en Edge — pendiente reejecución de QA |

## 1. Diagnóstico

**Dónde está el clasificador.** En este repositorio, `raspberry/edge_agent/reglas/`
(agente `edge-agent` de la Raspberry del Gateway). El backend solo recibe
`clasificacion_rf55` ya calculada por `RecibirEventoEdgeDTO`, así que G38 no se
puede validar desde el repo del backend: por eso los tres `SKIPPED`. El simulador
existe: `raspberry/scripts/inyectar_lecturas.py` corre el agente real sin
hardware ni broker.

Al provocar las tres condiciones contra el clasificador real aparecieron
**dos defectos** y una diferencia con la matriz:

| Condición | Antes | ¿Defecto? |
|---|---|---|
| Variable sin ningún umbral (TC-083) | Sin evento ni registro; el contrato lo definía como "no es error" | Diferencia con la matriz, que espera `ERROR_CONFIGURACION` |
| Umbral con bandas en 0–0 (TC-095) | `ACK_UMBRAL` **OK**, se guardaba y **toda lectura salía `CRITICO`** | **Sí** |
| Umbral sin bandas `precaucion`/`critico`, o con huecos (TC-122) | `ACK_UMBRAL` **OK**; lo de fuera de la banda `normal`, o lo que caía en un hueco, salía **`CRITICO` inventado** | **Sí** |
| Umbral con `valor_min` = `valor_max` = 0 | `ACK_UMBRAL` `ERROR` | No (ya se rechazaba) |
| Porcentaje de desviación | El Edge no lo calcula: no hay división | No |

El Edge solo validaba que cada banda tuviera límites numéricos, no la forma del
conjunto. El backend sí la exige (rechaza otra con `SOLAPAMIENTO_NIVELES`), pero un
umbral que llegara de otra forma, o que hubiera dejado guardado un firmware
anterior, se aceptaba y producía severidades que nadie había definido.

## 2. Cambios necesarios para QA

### 2.1 Comportamiento esperado

| Condición | Resultado en el Edge |
|---|---|
| Variable sin umbral (TC-083) | **Un** `ERROR_CONFIGURACION` por variable, sin `severidad`, con `metadata_edge.motivo` = `sin umbral RF-17 para la variable en este Edge`, `variable` y `severidad_invalida: true`. Las lecturas siguientes no se publican de nuevo: quedan en el historial local como `ERROR_CONFIGURACION` `LOCAL`. Las demás variables se siguen clasificando |
| Umbral que no cumple la forma, al recibirlo (TC-095/122) | `ACK_UMBRAL` `ERROR` con el `motivo`; no se guarda |
| El mismo umbral ya guardado | `ERROR_CONFIGURACION` (una vez por umbral y versión) con `motivo`, `id_umbral_ambiental`, `severidad_invalida: true`, **sin `severidad`**; nunca `DESVIACION_SIMPLE` |
| En todos los casos | La lectura cruda sale como telemetría (`sgpmp/<serial>/telemetry`) para que el backend la procese con RF-62. No se inventa una clasificación |

Forma válida de un umbral (la misma del backend): `valor_min < valor_max` y las
bandas `normal`, `precaucion` y `critico`, una vez cada una, de ancho mayor que 0,
contiguas y cubriendo exactamente `[valor_min, valor_max]`. Un límite en 0 es
válido. Detalle y motivos: `CONTRATO_EVENTO_EDGE.md` §3.

```json
{
  "clasificacion_rf55": "ERROR_CONFIGURACION",
  "variables_involucradas": [{"tipo_variable": "temperatura_ambiente", "valor": 35.0, "unidad": "C"}],
  "metadata_edge": {
    "regla_aplicada": "UMBRAL_AMBIENTAL",
    "id_umbral_ambiental": 7,
    "version_umbral": "2026-10-05T17:59:58+00:00",
```

Sin campo `severidad`. El valor 35.0 también sale como telemetría cruda.

### 2.3 Ejecución contra el motor real

La configuración se prepara por el mismo camino que usa el broker (comandos
`UMBRAL_AMBIENTAL`). `umbrales_guardados` siembra un umbral directo en disco, como
lo habría dejado un firmware anterior.

```bash
cd raspberry
python scripts/inyectar_lecturas.py scripts/casos_rf55.json -v --caso "E1 TC-M03-083 variable sin umbral: un ERROR_CONFIGURACION y siguen las mediciones"
python scripts/inyectar_lecturas.py scripts/casos_rf55.json -v --caso "E2 TC-M03-095 umbral en cero se rechaza (ACK_UMBRAL ERROR)"
python scripts/inyectar_lecturas.py scripts/casos_rf55.json -v --caso "E3 TC-M03-095 banda de ancho cero se rechaza (ACK_UMBRAL ERROR)"
python scripts/inyectar_lecturas.py scripts/casos_rf55.json -v --caso "E4 TC-M03-095 un limite en 0 es valido y no divide por cero"
python scripts/inyectar_lecturas.py scripts/casos_rf55.json -v --caso "E5 TC-M03-122 umbral sin bandas de severidad se rechaza (ACK_UMBRAL ERROR)"
python scripts/inyectar_lecturas.py scripts/casos_rf55.json -v --caso "E6 TC-M03-122 umbral guardado sin severidad: no inventa CRITICO"
pytest tests/test_errores_configuracion.py -v
```

Con `-v` el inyector imprime cada evento publicado, el historial local (la
bitácora: filas `DIRECTA` y luego `LOCAL`) y los ACK de error.

| Caso | Matriz | Qué demuestra |
|---|---|---|
| E1 | TC-083 | Error publicado una vez; las siguientes lecturas quedan `LOCAL`; la FR, con umbral, se sigue clasificando en las 3 capturas |
| E2, E3 | TC-095 | Umbral en cero y banda de ancho 0: `ACK_UMBRAL` `ERROR`, nunca `CRITICO` |
| E4 | TC-095 | Un límite en 0 es válido: T = 0 normal, T = 9 `CRITICO` |
| E5 | TC-122 | Umbral sin severidades: `ACK_UMBRAL` `ERROR` |
| E6 | TC-122 | Ya guardado: `ERROR_CONFIGURACION` con `severidad_invalida: true`, sin severidad |

### 2.4 Cambio visible en otros casos

Un caso que no configura umbral para alguna variable (pasa en los de reglas
compuestas: HR, pH, OD, NH3, CO2) recibe también ese `ERROR_CONFIGURACION`. En
`casos_rf55.json` se declara en `esperado_sin_umbral` y el inyector lo compara
aparte de `esperado`. El caso S8 pasa de "sin evento" a `ERROR_CONFIGURACION`, y
P1 y P3 suman la fila del error en su historial esperado. En un despliegue real,
**cada variable que mide un nodo necesita su umbral RF-17** en la plataforma, o
reporta este error una vez cada vez que arranca el servicio.

## 3. Decisión y abordaje en el repositorio

### 3.1 Decisiones

| # | Decisión | Motivo |
|---|---|---|
| D1 | Variable sin umbral → `ERROR_CONFIGURACION`, una vez por variable (aprobado) | Lo pide la matriz; uno por lectura saturaría el rate limit del backend |
| D2 | Forma del umbral igual a la del backend (aprobado) | Es la que el backend ya garantiza (`SOLAPAMIENTO_NIVELES`); se rechaza lo que de otra forma inventaría severidades |
| D3 | Misma validación al recibir y al evaluar (`motivo_niveles`) | El ACK lo rechaza y un umbral viejo guardado en disco tampoco clasifica |
| D4 | `severidad_invalida: true` en `metadata_edge`, sin `severidad` | Evidencia de TC-122 sin cambiar el DTO: el backend persiste `metadata_edge` íntegro |
| D5 | Lecturas siguientes al historial local (`LOCAL`, sin `id_evento`) | Bitácora de cada lectura sin clasificar sin repetir el evento |
| D6 | No se agrega una interfaz de configuración local | El camino real es el comando `UMBRAL_AMBIENTAL`; el simulador usa ese mismo camino, y `umbrales_guardados` cubre el umbral ya guardado |

### 3.2 Cambios de código

| Archivo | Cambio |
|---|---|
| `raspberry/edge_agent/reglas/evaluador.py` | `motivo_niveles()`; `evaluar_simple` da `ERROR_CONFIGURACION` (`SIN_UMBRAL` o el motivo) con `variable` y `severidad_invalida` |
| `raspberry/edge_agent/commands.py` | `handle_umbral` valida con `motivo_niveles` |
| `raspberry/edge_agent/agent.py` | Deduplicación del error por umbral y versión, o por variable; las repeticiones van al historial `LOCAL` |

| `raspberry/scripts/casos_rf55.json` | Casos E1–E6; S8, P1, P3 y los de reglas compuestas declaran `esperado_sin_umbral` |

| `docs/CONTRATO_EVENTO_EDGE.md`, `docs/ARQUITECTURA.md` | §2 y §3 (forma válida, motivos, uno por variable), casos E1–E6 |

### 3.3 Verificación

- Sondas previas: bandas 0–0, solo `normal` y con huecos daban `ACK_UMBRAL` OK y `CRITICO`. Ahora dan `ACK_UMBRAL` `ERROR` o `ERROR_CONFIGURACION`.
- Mutación: con `motivo_niveles` anulado, fallan 12 de las 15 pruebas nuevas y los casos E2, E3, E5 y E6.
- `pytest`: 506 pruebas OK (1 omitida: `test_systemd.py` requiere sockets Unix, solo Linux), incluidas las 68 de RF-55 extremo a extremo.
- Inyector de QA: 54/54 casos OK.
- `ruff check` y `ruff format --check`: sin hallazgos.
